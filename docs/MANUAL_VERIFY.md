## 5. ★ "자동 검증이 불가능하다" 고 적은 것 — **그 결론이 틀렸다** (2026-09-28 교정)

### 교정 전 기록 (틀림)
> `System Events` 의 `entire contents of window` 가 **0개**를 반환한다. SwiftUI 내용이
> 보조기술(AX) 계층에 노출되지 않아 **클릭 조작이 불가능**하고, 스크린샷도 팝오버를 열려면
> 먼저 클릭해야 한다.

### 왜 틀렸는가 — 앱이 아니라 **질의 방법**의 문제였다
`0` 이었다는 사실은 사실이었다. 틀린 것은 **"그래서 비어 있다" 는 해석**이었다.

| 잘못된 측정 | 실제로 한 일 | 결과 |
|---|---|---|
| `entire contents of window` | SwiftUI 트리에서 `entire contents` 의 **재귀가 실패**한다. `UI elements` 로 한 단계는 들어간다 | `0` |
| 앱이 frontmost 아닌 상태에서 조회 | **어떤 창이 key 인지가 트리를 정한다** — 앱 전체를 활성화하면 대시보드 창이 올라가며 **로그 창의 서브트리가 잘린다** | 요소 수가 실행마다 `247~270` 으로 흔들림 |

### 지금 방법 — `scripts/ax-dump.swift`
`AXChildren` 을 직접 따라가는 **Swift 도구**를 넣었다. `entire contents` 를 쓰지 않는다.

```bash
swift scripts/ax-dump.swift "Relay Console" --window=로그 --buttons   # 상호작용 요소 열거
swift scripts/ax-dump.swift "Relay Console" --click "기기에서"         # 배지 클릭 → 팝오버 열기
swift scripts/ax-dump.swift "Relay Console" --click "기본값 복원"       # 팝오버 안 클릭
```

| 규칙 | 이유 (모두 실측) |
|---|---|
| `--window=<이름>` 으로 **그 창을** key 로 만든다 | 앱 전체 활성화는 다른 창을 올려 서브트리를 자른다 |
| **`--click` 에서는 초점을 건드리지 않는다** | 로그 창을 key 로 만들면 **팝오버가 닫힌다** → "대상 없음" 으로 조용히 실패 |
| `--window=` 는 인자 위치를 밀지 않게 먼저 뗀다 | 그러지 않으면 검색어가 `"--click"` 이 되어 **매칭이 조용히 실패** |
| 실패하면 "대상 없음" + 사용 가능한 이름을 **전부 보여준다** | 추측하지 않게 하는 장치 |

계측: 로그 창 AX 요소 **270개** · 배지 버튼이 `AXButton — 기기에서 3개 태그 제외` 로 노출.

### 이 교정으로 열린 것
- MANUAL_VERIFY 2~7번 → ✅ (위 표)
- 13번 → "읽히지 않는다" 는 **근거 없음**. AX 계층은 살아 있다. **읽는 소리**만 육안
- **실제 결함 1건 발견** — 팝오버가 태그를 켜는 즉시 닫혀 여러 개를 고를 수 없었다 (§9)

### 강제 종료(`pkill`)는 자동 검증했고, GUI 종료(⌘Q)도 자동 검증했다
두 경로 모두 adb 자식 0개 · 기기 `logcat` 0개로 계측 확인됨. **육안 항목이 아니다.**

## 6. 이 목록을 줄이는 방법

각 항목이 계측으로 대체 가능한지 먼저 본다.

| 항목 | 대체 가능? | 어떻게 |
|---|---|---|
| 배지 표시 | ✅ 완료 | 스크린샷 + `ps` 로 adb 인자 확인 |
| 태그 제외가 기기에 반영 | ✅ 완료 | `ax-dump --click` → `ps` 로 `:S` 인자 확인 |
| 대소문자 무시 검색 | ✅ 완료 | `Scheduler` 표본으로 문자클래스 합집합 실측 |
| **팝오버 레이아웃·문구** | ✅ 완료 | **AX 트리가 열리므로 가능했다** (2~7번 · §5) — 스크린샷으로 눈으로 확인 |
| 언어 전환 | ❌ | 시스템 설정 변경이 필요 |

## 7. 커밋 훅 (2026-09-28 설치)

`scripts/git-hooks/pre-commit` + `git config core.hooksPath scripts/git-hooks`

- **한자 혼입 · U+FFFD · 충돌 마커**를 커밋 전에 검사해 **막는다**
- **스테이징된 파일만** 검사한다 (전체를 보면 커밋과 무관한 잔재로 막힌다)
- **대상 0건이면 조용히 통과하지 않고 알린다** — "아무것도 안 보고 0건" 사고를 막기 위해
- 우회가 필요하면 `git commit --no-verify` (사유를 PR 본문에 남길 것)
- 설치 상태는 **저장소 로컬 설정**이라 clone 을 다시 하면 사라진다 → 아래 §8

## 8. 다음 사람이 또 잊을 수 있는 것

`core.hooksPath` 는 `.git/config` 에 있어 **커밋에 딸려가지 않는다.** 새 머신에서 clone 하면
훅이 조용히 사라진다. 두 가지를 남긴다:

1. `README.md` 또는 `AGENTS.local.md` 에 **설치 한 줄**을 남길 것
2. 더 확실하게 하려면 저장소에 `scripts/install-hooks.sh` 를 두고 새로 클론한 뒤 한 번 돌리게 한다
   (이번 세션에서 만들지 않은 이유: `git config` 를 바꾸는 동작이라 **사용자 명령 후** 실행해야 한다)

## 9. 자동화로 찾은 실제 결함 (2026-09-28)

### 9.1 팝오버가 태그를 켜는 즉시 닫혔다 — **여러 개를 고를 수 없는 상태**

태그 하나를 토글하면 `@Published` 변경 → 부모 `body` 재평가 → `.popover` 콘텐츠가 새로
만들어지며 SwiftUI 가 닫아 버렸다. **기능이 "한 번에 하나만"** 이었다.

부수 손실도 컸다 — 태그를 켤 때마다 `adb` 를 재기동하는데, 재기동할 때마다 링 버퍼를
**처음부터 다시 받는다**(이 기기에서 1.6만 줄). 태그 3개를 고르면 3번 받는다.

**고친 것** — 재기동을 **0.6초 디바운스**로 미룬다.

- 체크박스 표시는 `setExcluded` 로 **즉시** 바뀌고(`tagStats` 갱신) → 연속 클릭 가능
- 배지는 `appliedExcludedTags`(실제로 적용된 값)를 말하므로, 0.6초 동안 옛 값인 것은
  **"아직 적용 안 됨" 이라는 참이다**
- 실측: `Watchdog` + `minksocket` 연속 클릭 → adb 인자 5개, 배지 `5개`, 수신량 11,445 → 4,769줄

**남는 성질(의도)** — 마지막 토글 0.6초 뒤 스트림이 재기동되면서 팝오버는 닫힌다.
열린 채로 확정해야 할 이유가 없으므로 그대로 둔다. **자동 검증은 이 창 안에서 해야 한다**
(§5 의 규칙).

### 9.2 원인 미확정 관측 1건 — 되돌아가지 않음을 확인했다

한 번, 태그 5개 상태에서 **어떤 조작도 하지 않았는데** 저장 배열이 기본 3종으로
돌아간 적이 있다. 원인은 **확정하지 못했다.** 짐작으로 채우지 않는다.

확인한 것:

- 새 크래시 리포트 없음 (최신 `02:45` 는 이미 고친 `LineParser` 건)
- 배지 버튼에 복원 로직 없음 — `showingTagPicker = true` 뿐
- 5개 상태로 두고 **12초간 1초마다 감시** → 저장 5개 · adb 인자 5개로 **고정**, 되돌아가지 않음

**앞으로의 규칙**: `setExcludedTags` 는 이 앱에서 **저장 배열을 쓰는 유일한 곳**이다.
다음에 이 증상이 보이면 그 경로부터 본다. 이 항목은 **미해결로 남긴다** — 해결한 척하지 않는다.
