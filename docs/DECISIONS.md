## D1 — Sites·Jobs 제거, 기기 관제로 집중 (2026-10-05)

- **결정**: 사이트 업타임 감시(Sites)·하트비트 작업 감시(Jobs)를 앱에서 덜어냈다.
  Relay Console은 **기기 관제탑** 한 문장으로 설명된다.
- **사유**:
  1. 쓰는 사람이 없다 — 자운영 서버도 크론도 없으니 쓸 게 없었다.
  2. 기기 이벤트와 만나지 않는다 — 합쳐지는 곳이 브리핑 한 줄뿐이라 세 앱이 메뉴바를 나눠 쓰는 모양이었다.
  3. 기기가 너무 커졌다 — 관제センター로 시작했지만 실사용은 폰 관제에 쏠렸다.
- **다시 보지 않는다**: 사이트·작업 감시를 되살리자는 이야기가 나오면 이 D1을 먼저 읽는다.
  부활 재료는 git 히스토리에 있다 (`git log -- Sources/RelayConsole/Sites`).
  삭제된 것: `Sites/`·`Jobs/`(하트비트 8787 포함)·관련 Views·store·WatchKind 5종·MCP 도구 2종·L10n 111키·
  위젯/브리핑/Alerts/`/metrics`의 사이트·작업 파트. 위젯 스냅샷 스키마 v1 → v2.
- **다음**: 기기 관제 확장 — 자동 진단(원인 추출·범인 파악·리포트). 재료 추출은 `docs/research/`에서.

## D2 — 위젯(WidgetKit 3종) 제거 (2026-10-17)

- **결정**: macOS 위젯 3종(small/medium/large)·App Group 스냅샷 파이프라인·`relayconsole://` 딥링크를 제거했다.
  제거 범위: `Sources/RelayWidget`(529) + `Sources/RelayWidgetCore`(167) + 앱측 `WidgetSnapshotSync`·`WidgetDeepLink`(192)
  + `WidgetSnapshotTests`(244) + `WidgetXcode/`(xcodegen) + `Entitlements/RelayWidget.entitlements` + `widget.*` L10n 12키.
- **사유 (실측)**:
  1. **정보 중복** — 위젯이 보여주는 값(기기·배터리·발열·이벤트·critical)은 팝오버·메뉴바 배지와 같다.
     앱은 이미 메뉴바 상주형이라 "클릭 없이 상시 확인"이라는 위젯의 이점이 팝오버 한 번과 크게 다르지 않다.
  2. **빌드 결합이 비쌌다** — 위젯 appex는 SPM으로 못 만들어 **xcodegen + xcodebuild 필수**(없으면 빌드 실패).
     서명 팀이 어긋나면 위젯 갤러리에 안 뜨는 취약점까지 떠안았다. 제거로 빌드가 SwiftPM 단독으로 돌아온다.
  3. **배포 채널 없음** — 앱은 비샌드박스(adb·scrcpy)라 **Mac App Store 불가** → "위젯 3종"의 마케팅 가치가 0이다.
  4. **변화 없음** — 2026-09-25 도입 후 3주간 위젯 코드 변경 0건(Sites·Jobs 제거에 따른 스냅샷 정리 1건 제외).
- **잃는 것**: 데스크톱/알림센터 상시 노출 표면 1개, `relayconsole://<target>` 외부 딥링크.
  위젯 LOC 1,132(전체의 2.9%)·L10n 12키·경쟁 리서치 M5 문구 1개는 문서에 기록으로 남는다.
- **다시 보지 않는다**: 위젯 부활 재료는 git 히스토리에 있다 (`git log -- Sources/RelayWidget WidgetXcode`).

## D3 — 한 폰이 여러 전송으로 잡혀도 **목록만** 합친다 (연결은 끊지 않는다) (2026-10-17)

- **결정**: `DeviceInventory.group` + `DeviceTransportMenuItems` — `physicalId`(`ro.boot.serialno`)가 같으면
  기기 선택(콘솔 칩 · 팝오버 메뉴 · 파일 탐색기 메뉴)에서 **한 줄**로 보여주고, 전송 배지(USB · 무선 · 5555 레거시)로 경로를 밝힌다.
  대표 전송 우선순위 = **온라인 → USB > 무선 디버깅 > 레거시 tcpip**(시리얼순 고정). 같은 폰의 나머지 전송은
  하위 메뉴("다른 연결 N개")에 남겨 **명시적으로** 고를 수 있게 한다(미러링 대상 고르기).
- **하지 않는 것 — 이게 결정의 핵심**: 무선이 잡히면 레거시 5555를 자동 `disconnect` 하는 식의 **중복 전송 자동 정리**는 하지 않는다.
  전송을 끊으면 그 전송으로 도는 **미러링·파일 전송이 즉시 죽는다**.
  실측 재현(2026-10-17): 미러링 중 `adb disconnect <그 전송>` → scrcpy 즉시 종료 · 앱 오류창 `ERROR: Demuxer error`.
  그래서 정리 로직에도 **미러링 중 시리얼은 예외**로 둔다(`mirroredSerial` 가드 · `disconnectStaleEndpoints`/`adoptEndpoint`/`connectWithRetry`).
- **사유(실측)**: S22 하나가 `192.168.86.49:5555`(레거시 tcpip)와 `192.168.86.49:45325`(무선 디버깅)로 **동시에** `device` 였고
  기기 선택에 같은 폰이 두 줄로 떴다(USB까지 꽂으면 세 줄). adb 의 기기 키는 **전송**이라 앱이 합치지 않으면
  사용자는 어느 줄을 눌러야 하는지 알 수 없다. 5555는 재부팅하면 닫히고 USB로만 다시 켤 수 있는데,
  무선 디버깅 포트는 mDNS 광고로 되찾을 수 있다 — 그래서 대표를 무선으로 둔다.
- **남는 한계**: 지표·일일 집계·이벤트는 여전히 **전송(시리얼) 단위**로 저장된다(대표 전송만 화면에 쓰인다).
  물리 기기 기준으로 합칠지는 별도 판단 — TODO T-2026-10-17-10 참조.
- **다시 보지 않는다**: "중복 전송 자동 정리"를 다시 제안하려면 위 미러링 실측을 먼저 읽는다.

## D4 — [끊기] 는 **자동 재연결에서도 제외**한다 (되돌리는 문은 화면에 남긴다) (2026-10-18)

- **결정**: 사용자가 시트의 **[끊기]** 를 누른 기기는 ① 지금 연결을 끊고 ② **기억(`relay.wifi.endpointsByDevice`)에서 지워**
  자동 재연결 대상에서 뺀다(세션 표식 `userDisconnectedEndpoints` + `forgetEndpoint`). 기억이 없으므로 **앱을 재시작해도 되살아나지 않는다**.
- **되돌리는 문**: 시트의 [발견된 기기] 행 **[연결]** 또는 [수동 연결] 로 직접 이으면 표식이 풀리고 기억이 다시 저장된다 —
  "그 뒤로는 자동"으로 복귀한다. [끊기] 직후 상태 줄이 그 사실을 말한다:
  `연결 해제됨 — 자동 재연결에서 뺐습니다 · 위 [발견된 기기]에서 다시 연결하세요`.
- **사유(실측 2026-10-18)**: 종전에는 기억이 남아 **1분 뒤 앱이 스스로 되살렸다**(사용자가 끊은 기기가 다시 붙는다).
  사용자가 실제로 겪은 혼동도 이 지점이었다 — [끊기] 뒤 무선 디버깅을 다시 켰는데 앱이 안 붙자 "왜 안 붙지?".
  그때는 반대로 **아무 문구도 없어서** 알 수 없었다 → 문구로 안내하는 것이 이 결정의 절반이다.
- **하지 않는 것**: [끊기] 뒤에도 계속 감시해 자동으로 다시 붙이는 동작(옛 동작). 그게 필요하면 [끊기] 대신
  폰에서 무선 디버깅을 끄는 것이 맞다 — 그 경우는 앱이 "다시 찾는 중"으로 정직하게 표시하고 되찾는다(T-4 · 49·52 통과).
- **다시 보지 않는다**: "[끊기] 했는데 왜 다시 안 붙나"는 버그가 아니다. 위 되돌리는 문을 먼저 확인한다.

## D5 — mDNS 인스턴스 이름은 **공백을 포함할 수 있다** — `" (2)"`도 정식 형식 (2026-10-19)

- **결정**:
  1. `adb mdns services` 파싱은 **토큰 수를 고정하지 않는다** — 마지막 = `host:port`, 그 앞 = 서비스 종류,
     **나머지 전체 = 인스턴스 이름**. macOS mDNSResponder가 같은 인스턴스의 두 번째 등록을 `" (2)"`로 개명하기 때문이다.
  2. `adb devices` 파싱은 **TAB 우선** — serial과 상태는 TAB으로 구분되고, mDNS serial은 공백을 포함한다.
  3. 재연결 base 후보는 **기억된 `IP:포트`를 보존**한다. `reconnectCandidateOrder`가 돌려주는 IP에 `:5555`를
     붙이는 것은 **다른 호스트의 폴백**에만 쓴다.
  4. `..._adb-tls-connect._tcp` / `..._adb._tcp` serial은 **network** 전송이다(USB 아님).
- **사유(실측 2026-10-19 · S22 SM-S901N)**:
  - 폰은 정상이었다 — 무선 디버깅 `46249` 열림(`adb connect` 성공) · 레거시 `5555` 닫힘(`service.adb.tcp.port` 빈 값).
    Android 11+ 무선 디버깅은 랜덤 포트를 쓰고 5555는 USB `adb tcpip 5555` 전용이다.
  - mDNS 광고가 같은 인스턴스로 두 번 떴다: `39775`(죽음 · refused) + `" (2)"` `46249`(살아있음).
    3토큰 고정 파서가 **4토큰인 `" (2)"` 줄을 통째로 버려** 살아있는 포트가 사라졌다.
  - `adb devices`도 `adb-... (2)._adb-tls-connect._tcp<TAB>device`라 첫 공백에서 자르면 상태가 `(2)...`가 되어
    **연결된 기기를 '연결 끊김'으로 오판**했다.
  - 기억은 죽은 `192.168.86.49:39775`였고, 재연결 base가 이를 `:5555`로 덮었다. 게다가 `adb mdns services`가
    간헐적으로 0건(10회 중 1회)이라 그 틱에는 폴백이 5555뿐이었다.
- **하지 않는 것**: mDNS 광고를 그대로 믿지 않는다 — 여전히 포트 프로브(`nc -z`)로 살아있는 후보만 `connect`한다.
  목록에서 죽은 광고를 자동으로 숨기는 것은 별도 판단(사용자가 주소를 직접 고를 수 있는 정보라 남긴다).
- **다시 보지 않는다**: "무선 디버깅인데 `:5555`가 왜 안 되나"는 버그가 아니다. Android 11+는 랜덤 포트이고,
  5555는 USB로 `adb tcpip 5555`를 걸 때만 열린다.

## D6 — 앱 설치·삭제는 **사용자 명시 동작**에만, MCP·감시 경로에서는 불가 (2026-10-24)

- **결정**:
  1. `adb install`·`adb uninstall`·APK 백업은 **앱 관리 시트에서 사용자가 누른 동작**으로만 실행한다.
     MCP(`RelayMcpCore`)·감시 엔진·자동 재연결·스케줄 경로에는 쓰기 도구를 추가하지 않는다.
     `RelayMcpCore`의 **읽기 전용 계약은 그대로**다.
  2. 기기 설정 쓰기(`settings put`, Play 프로텍트 해제, 설치 검증기 끄기)는 하지 않는다.
     차단되면 **원인과 사용자가 직접 해제할 방법만** 안내한다.
  3. `-g`(런타임 권한 일괄 허용)는 기본 OFF. `-d`(다운그레이드)·`-t`(테스트 APK)도 기본 OFF.
  4. 삭제 기본값은 **앱+데이터 완전 삭제**다. `-k`(데이터 유지)는 보조 선택이며,
     확인창에 "데이터는 복원되지 않는다"를 고정 표시한다. APK 백업은 **앱만** 복원한다고 명시한다.
- **사유**: 이 앱의 정체성은 "감시(읽기) 관제탑"이다. 설치·삭제는 기기 상태를 바꾸는 예외 동작이므로
  자동화 표면과 분리해야 사고가 나지 않는다. 기존 `pm uninstall -k` 기본값은 "삭제"라는 말과
  실제 결과(데이터 잔존)가 달라 사용자가 저장공간 회수를 못 하는 문제를 만들었다.
- **하지 않는 것**: 시스템 앱 완전 제거(루트), 데이터 백업/복원, Play 프로텍트 자동 해제.
  시스템 앱은 C 단계에서 `--user 0` + `cmd package install-existing` 복원만 제공한다.
- **다시 보지 않는다**: "MCP에서 앱 설치 도구도 넣자"·"삭제 기본을 `-k`로 되돌리자"는 이 D6을 먼저 읽는다.

## D7 — 번들·아이콘은 **앱 안에서 직접 파싱**, 아이콘 캐시는 30일·50MB (2026-10-24)

- **결정**:
  1. ZIP 해제·`AndroidManifest.xml`(AXML)·`resources.arsc`(ARSC) 파싱을 **앱 안에서 직접 구현**한다.
     외부 프로세스는 `adb`·`scrcpy` 둘로 유지한다 — `unzip`/`aapt`/`apkanalyzer` 를 부르지 않는다.
  2. ZIP 은 **필요한 엔트리만 스트리밍으로** 꺼낸다. `300MB` APK 를 통째로 메모리에 올리지 않는다.
     상한은 엔트리 256개 · 엔트리 512MB · 합계 8GB, 절대경로·`..`·백슬래시는 **열기 전에 거부**한다.
     ZIP64·암호화·미지원 압축은 조용히 잘못 읽느니 `unsupported` 로 실패한다.
  3. 분할 선택 실패 시 **전체 포함으로 폴백**한다. 설치가 되고 용량만 커지는 쪽이, 빠뜨려 설치가
     실패하는 쪽보다 낫다. 모르는 설정 토큰도 포함한다. 단 `standalones/` 는 splits 가 있으면 제외한다.
  4. OBB 는 `manifest.json` 의 `install_path` 를 존중하되, 경로 순회를 제거한 뒤
     `Android/` 로 시작하지 않으면 `/sdcard/Android/obb/<pkg>/<파일명>` 으로 고정한다.
     OBB 는 **앱 설치가 성공한 뒤에만** 복사한다(실패한 설치의 부산물을 기기에 남기지 않는다).
  5. 아이콘은 **기본 ON**, 토글로 끌 수 있다. 캐시는 256pt@2x(512px) PNG · **30일 · 50MB**,
     넘으면 오래된 것부터 삭제 · 동시 2개 · 보이는 행만. 실패는 색+이니셜 타일로 폴백하고
     사용자에게 오류를 띄우지 않는다(목록 가독성은 부가 기능이다).
- **사유**: 번들 설치와 아이콘은 "있으면 좋은" 기능이지만, 외부 바이너리를 늘리면 배포·서명·샌드박스
  문제가 따라온다. 파서를 직접 두면 테스트로 고정할 수 있고(합성 ZIP·AXML 픽스처), 실패 지점을
  사용자 문구로 구분할 수 있다. 아이콘은 네트워크 ADB 에서 대역폭을 먹으므로 상한·동시성이 필요하다.
- **하지 않는 것**: APK 재서명·디컴파일·DEX 분석, 아이콘 서버 업로드, OBB 자동 다운로드.
- **다시 보지 않는다**: "ZIP 은 `unzip` 부르면 되지 않나"·"아이콘 캐시를 무제한으로 두자"는 이 D7을 먼저 읽는다.

## D8 — 시스템 앱은 **`--user 0` 비활성·복원만**, 핵심 구성요소는 하드 블록 (2026-10-24)

- **결정**:
  1. 시스템 앱 "제거"는 `pm uninstall --user 0 <pkg>` 로만 수행한다. 시스템 파티션의 APK 는
     지우지 않으므로 `cmd package install-existing --user 0 <pkg>` 로 언제든 복원할 수 있다.
     루트·`pm uninstall`(전체)·`pm disable`(다른 사용자 영향)은 쓰지 않는다.
  2. **하드 블록** — `android`, SystemUI, Settings, Shell, PackageInstaller( AOSP·Google),
     PermissionController, Phone/Telecom, Settings/Contacts/Media Provider, GMS·GSF, Play 스토어,
     런처(접두사: `com.android.launcher*`, Samsung·Xiaomi·Nexus·OnePlus·OPPO·vivo·Transsion).
     UI 는 잠금 아이콘만 보여주고, 컨트롤러도 실행 직전에 한 번 더 검사한다(이중 방어).
  3. 그 외 시스템 앱은 **체크박스 2개**를 모두 켜야 비활성화된다. 하나는 "이 사용자에서 앱·데이터가
     사라진다", 다른 하나는 "복원 가능 탭에서 되돌릴 수 있다"는 이해 확인이다.
  4. `복원 가능` 목록은 `pm list packages -u -s` 에서 현재 설치 목록을 뺀 **차집합**만 보여준다.
     사용자가 지운 서드파티 앱은 복원 대상이 아니다(그건 재설치로만 돌아온다).
  5. 복원은 APK 를 다시 설치하는 것이므로 **앱 데이터는 돌아오지 않는다**. 확인창과 탭 안내에
     이 사실을 고정 표시한다. 데이터 백업/복원은 여전히 OUT 이다.
- **사유**: 시스템 앱 비활성화는 "광고·블로트 제거"에 유용하지만, 잘못 고르면 부팅·잠금화면·설정
  진입이 깨져 기기를 사실상 못 쓰게 된다. 사용자 0 범위는 되돌릴 수 있는 최소 권한이고,
  하드 블록은 "복원 화면에 들어갈 수 없는 상태"를 만들지 않기 위한 안전장치다.
  체크박스 2개는 실수 클릭과 "완전 삭제"로의 오해를 동시에 막는다.
- **하지 않는 것**: 루트 제거, 시스템 파티션 쓰기, `pm disable-user --user 0` 이외의 비활성화,
  Play 프로텍트·설치 검증기 설정 변경, 시스템 앱 자동 정리 추천.
- **다시 보지 않는다**: "런처 정도는 꺼도 되지 않나"·"`pm uninstall` 로 완전히 지우자"·
  "복원하면 데이터도 돌아오지 않나"는 이 D8을 먼저 읽는다.

## D9 — 아이콘은 **벡터·적응형까지 직접 렌더**, 앱 이름은 같은 APK pull 에서 (2026-10-24)

- **결정**:
  1. 아이콘 후보는 **비트맵 우선**, 없으면 `anydpi` XML(적응형·벡터)까지 받는다. 확장자가 없는
     난독화 엔트리(네이버 웨일 `res/4jn` = WebP)도 ImageIO 로 읽어 후보로 인정한다.
  2. 적응형 아이콘은 108dp 캔버스의 **가운데 72dp 가 보이는 영역**이라는 규칙을 그대로 적용한다 —
     레이어를 1.5배 크기로 그린 뒤 중앙을 크롭한다(`rect = -size/4 … size*1.5`).
  3. 벡터 드로어블은 SVG 경로 문법 전체(M/L/H/V/C/S/Q/T/A/Z · 절대/상대 · 암시 L)를 직접 해석한다.
     호는 90° 이하 큐빅 베지어로 근사한다(CGPath.addArc 의 방향 규약에 기대지 않는다).
     `group` 변환·`clip-path`·그라디언트는 근사하고, 단색 레이어는 ARSC `colorValue` 로 채운다.
  4. 앱 이름은 `AndroidManifest.xml` 의 `android:label` → `resources.arsc` 문자열로 해석하며,
     값이 `@string/...` 참조면 **체인을 따라간다**(최대 8단계). 이름과 아이콘은 **같은 APK pull 1회**에서
     얻는다. 아이콘 토글 OFF 면 pull 자체가 없으므로 이름도 표시하지 않는다(패키지명만).
  5. 파서 상한은 "비정상적으로 큰 파일"만 막는다 — ZIP **150,000 엔트리**, 문자열 풀 **2,000,000개**.
     실질 방어선은 중앙 디렉터리 16MB·파일 크기 검사다(삼성 시스템 앱 실측 230,461개).
- **사유**: 현대 앱은 PNG 아이콘을 거의 두지 않는다(실측 12개 중 7개가 XML-only). PNG 만 지원하면
  실사용 대부분이 색 타일로 폴백해 기능이 사실상 죽는다. 외부 프로세스는 adb·scrcpy 로 제한했으므로
  `aapt`/`rsvg` 를 부를 수 없고, 최소 렌더러를 앱 안에 두는 것이 유일한 길이다.
  이름은 대역폭이 아니라 **해석**의 문제다 — `pm list` 에는 라벨이 아예 없다.
- **하지 않는 것**: `aapt`·`rsvg`·ImageMagick 호출, DEX/광고 SDK 분석, 아이콘 서버 업로드,
  애니메이션 벡터(AVD) 재생, 테마별(다크/라이트) 아이콘 선택.
- **다시 보지 않는다**: "PNG 아이콘만 있으면 되지 않나"·"아이콘을 못 찾으면 패키지명만 보여주자"·
  "희소 표는 예외 상황이니 무시하자"는 이 D9를 먼저 읽는다. 구글 포토·Gboard 는 실제로 희소 표를 쓴다.

## D10 — scrcpy 오디오 코덱은 **AAC 고정** (2026-11-05)

- **결정**: 미러 실행 인자에 `--audio-codec=aac` 를 항상 넣는다. 사용자 `customOpts` 는 뒤에 붙으므로
  `--no-audio`·`--audio-codec=opus` 로 덮어쓸 수 있다(자유 입력은 여전히 뒤에서 우선).
- **사유**: scrcpy 5.0.1 기본값은 opus 인데, LineageOS `herolte`(S7)에는 opus 인코더가 없어
  `Could not create default audio encoder for opus` 로 **오디오 초기화 실패가 영상 세션까지** 죽였다.
  AAC 는 AOSP 공통 인코더(OMX.google.aac.encoder)라 커스텀 ROM 에서도 열린다. 화질 손실은
  관제용 미러에서 문제되지 않고, 오디오를 아예 끄는 것보다 사용자 선택 폭이 넓다.
- **하지 않는 것**: 기기별 오디오 인코더 사전 탐지, opus 우선 후 실패 시 재시도(복잡도 대비 이득 없음).
  오디오 3택(그대로/끄기/기기에서도 재생)은 `PLAN_scrcpy_options` B급 후보로 남긴다.
- **다시 보지 않는다**: "기본 opus 로 두고 기기에서 실패하면 사용자가 옵션을 빼면 되지 않나" —
  실패하면 **영상까지** 안 나와서 사용자가 원인을 알 수 없다.

## D11 — GPU 사용률은 **kgsl → mali0 폴백** (2026-11-05)

- **결정**: `gpuBusy`·`gpuClk` 폴링을 `cat kgsl… 2>/dev/null || cat mali0… 2>/dev/null` 한 셸로 보낸다.
  Qualcomm 은 종전 그대로 `kgsl` 이 먼저 읽히고, Exynos 는 `norm_utilization`(0~100)으로 폴백한다.
- **사유**: GPU 카드가 `kgsl` 경로만 읽어 Exynos(Mali-T88x) 기기에서 사용률이 영구 공백이었다.
  sysfs 읽기 한 줄을 `||` 로 이어 붙이므로 **adb 호출 수는 늘지 않는다**(PollBatch 마커 계약 유지).
- **하지 않는 것**: `mali0/device/clock` 이 **화면 꺼짐 상태에서 0** 을 보고하는 것을 억지로 표시하지 않는다(0 은 값이 아니라 "보고 없음"). 화면이 켜지면 260 MHz 를 정상 보고한다. Adreno/Mali 외(GPU 없음)는 종전처럼 공백으로 둔다.
- **다시 보지 않는다**: "GPU 는 Qualcomm 만 지원하면 된다" — 사용자의 관제 대상에 Exynos 기기가 있다.

## D12 — 데이터가 없을 때는 **"없다"와 "못 준다"를 구분**한다 (2026-11-05)

- **결정**: 수집 실패·미지원과 "실제로 0" 을 **같은 문구로 뭉개지 않는다**. 앱별 네트워크가
  안 나오는 기기는 `아직 트래픽 없음` 대신 **`이 기기는 앱별 트래픽을 보고하지 않습니다`** +
  `지금 인터페이스 합계 ↑… ↓…` 를 표시한다.
- **사유**: S7(LineageOS 21)에서 다운로드 중인데 NETWORK 카드는 `↑48.1 ↓72.3 KB/s` 그래프가
  정상인데 앱별 창은 "아직 트래픽 없음" 이었다. 사용자는 **앱이 거짓말한다**고 느낀다(실제 제보).
  원인은 ROM(netd 가 BPF map 미핀 → `dumpsys netstats detail` 에 UID 바이트 0,
  `/proc/net/xt_qtaguid/stats` 도 0바이트)이므로 앱이 고칠 수 있는 부분이 아니다.
  고칠 수 없는 것은 **고칠 수 없다고 말하는 것**이 정직한 표시다.
- **하지 않는 것**: 미지원 기기에서 앱별 수치를 추정·보간하지 않는다. "총합을 앱 수로 나누기" 같은
  가짜 분배도 하지 않는다. root/BPF 를 요구하는 우회도 범위 밖.
- **다시 보지 않는다**: "그래도 뭔가 보여줘야 하지 않나" — 빈칸 대신 **이유**를 보여준다.
