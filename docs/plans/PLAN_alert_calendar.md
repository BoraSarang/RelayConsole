## 1. 왜 "직접 추가"인가 — 이 프로젝트의 원칙

`AGENTS.local.md` §4 [표시②] 와 §22-2 의 교훈("사람이 가둔 함정은 자동화 항목 뒤에 숨어 있다"):
- **판단은 사람에게 돌려야 한다.** 앱이 "이건 중요하니 일정에 넣어뒀어요" 라고 하면,
  캘린더가 **신뢰를 잃는다** — 알림마다 일정 늘어나는 앱은 사용자가 캘린더 권한을 끈다
- 충돌도 자동으로 판단할 수 없다. 같은 시각에 이미 일정이 있으면? 사용자가 모른다
- **되돌리기가 가능해야 한다.** 캘린더는 사용자 데이터다. 앱이 건드리면 망가뜨릴 수 있다

→ **`Button` 하나.** 누르면 그 1건을 캘린더에 넣는다. 판단은 전부 사용자.

---

## 2. 범위 — "확장" 이 아니라 **"덮어쓰기"**

### 2-1. 하는 것
- `CalendarBridge` — `EKEventStore` 로 **일정 1건 추가** (읽기/조회 아님)
- 알림 항목의 "캘린더에 추가" 액션 → 해당 `WatchEvent` 를 일정으로
- **쓰기 전용** 접근만 요청 (`requestWriteOnlyAccessToEvents`) — 읽을 권한은 요구하지 않는다
- 사유가 드러나는 상태: 권한 없음 / 캘린더 없음 / 성공

### 2-2. **안 하는 것** (이유 남김)
| 안 하는 것 | 이유 |
|---|---|
| **읽기**(일정 조회) | 쓰기만 하면 된다. 읽기 권한까지 요구하면 **과한 권한**이다 |
| 자동 삽입 | §1 — 판단은 사람 |
| 반복 규칙(매일/매주) | 알림은 매번 발생한다. 반복이면 캘린더가 금방 넘친다 |
| 알람(`EKAlarm`) | 캘린더가 이미 알림을 준다. **이중 알림**이 된다 |
| `NSCalendarsFullAccessUsageDescription` | 쓰기 전용이면 이것까진 필요 없다 — **최소 권한** |
| 충돌 검사 | 판단을 앱이 대신하게 된다 (§1) |

## 3. 정직성 규칙

| 상황 | 표시 | 이유 |
|---|---|---|
| 권한 없음 | **사유 그대로** — "캘린더 권한이 필요합니다" | 실패를 숨기지 않는다 |
| 캘린더가 하나도 없음 | "먼저 캘린더를 만드세요" | **"없음" 과 "실패" 를 구분**한다 |
| 성공 | 일정 제목에 기기·사유 | 무엇이 들어갔는지 즉시 알 수 있다 |
| 이미 넣은 알림 | 버튼 비활성 + "넣음" | **같은 알림을 두 번 넣지 않는다** |

**기록 남김**: 캘린더에 넣었다는 사실을 앱 안에도 남겨야
"나중에 누가 이걸 넣었나" 를 알 수 있다. `WatchEvent.note` 에 표시.

## 4. 일정 내용 — 무엇을 넣는가

| 항목 | 값 | 이유 |
|---|---|---|
| 제목 | `<사유> · <기기>` (기존 알림의 title+detail) | 그대로 옮기면 맥락이 유지된다 |
| 시작 | **지금 + 15분** | 지금부터 언제 볼지 — 기본값은 짧게 |

| 알람 | **없음** | 캘린더가 이미 알린다 |
| 캘린더 | `defaultCalendarForNewEvents` | 사용자가 정한 기본. **앱이 캘린더를 고르지 않는다** |
