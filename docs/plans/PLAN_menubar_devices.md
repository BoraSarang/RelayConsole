# PLAN_menubar_devices — 메뉴바 기기별 속도 열 (DroidRelay형)

> 2026-10-13 · 조사+제안만 (코드 없음) · T-13-4 잔여(메뉴바)는 폐기됐으므로 본 PLAN이 대체
> 목표: 1대면 1열, 2대면 2열. 어느 열이 어느 기기인지 식별 가능. 한 번에 제대로.

## 1. 조사 결과

- **성능 영향 0**: 틱마다 전 기기를 병렬 배치로 이미 전수 수집 (`DeviceMonitor.tick` task group).
  열 추가는 표시 전용 — 기기 CPU·배터리·adb 바이트·폴링 주기 전부 불변. 맥도 텍스트 1열 추가 수준.
- **식별 수단 없음**: 기기별 색 미존재, 목록 순서는 adb 출력 순서라 틱마다 바뀔 수 있음 (`serials = found`).
  → 열 순서(serial 정렬 고정) + 식별자(색점) 둘 다 새로 만든다.
- **행·포맷·기하**: DroidRelay 이식분 재사용 (9pt mono-digit·화살표 이미지·"888M" 고정폭·compact `23K`/`—`).
  열 의미만 바뀜: 기존(앱+기기) → **기기+기기**.

## 2. 권장안: 고정 순서 + 색점 식별 (구현됨, T-2026-10-13-4)

- 열: 온라인 기기만, serial 오름차순 고정, 최대 2열 (3대째부터 자름 — 폭). 없으면 아이콘만.
- 셀마다 4pt 색점: serial 해시(`deviceColorIndex`, Swift hashValue 금지 — 실행마다 바뀜) → 6색 다크 안전 팔트.
  같은 점을 팝오버 기기행 앞에 표시 (범례).
- 행 높이 실측 고정 (`menuRowH`, DroidRelay 동일 수식) — SwiftUI 자연 높이에 맡기면 잘림 (2026-10-13 실측).
  값·화살표·점 전 행에 동일 높이 적용, 2행 합 22pt 보장.
- 심각도 점(아이콘 우상단, 최대 심각도)은 그대로 유지 — 열 색점과 충돌 없음.
- 설정: `relay.menubarSpeed`(표시 on/off) + `relay.menubarAll`(전 기기/선택 기기만, 기본 전 기기).
- 값 표기는 단위 항상 (DroidRelay와 의도적 차이 — 9pt에서 `124`·`—`는 깨져 보임): 1KB 미만 `124B`, 0은 `0K`,
  미측정만 `—`. `menuRateAlways` 순수 함수 + 테스트.
- L10n 신규 3키 × en/ko (`settings.menubarSpeed`, `settings.menubarAll`, `menubar.column`) + 접기 2키.
- 플로팅 접기 병행: 창별 collapsed, network창은 업·다운 숫자까지, 나머지 한 줄 값.

## 4. 범위 밖

- 앱 열(최다 UID) 부활 없음 — 열은 기기 전용. 앱 속도는 플로팅·팝오버에 그대로.
- 3대 이상 동시 표시 없음 (폭). 2대로 캡.
- B3·배너 이동 없음 (기존 결정 유지).
