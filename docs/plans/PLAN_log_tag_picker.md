## 0. 왜 이걸 하는가

직전 작업에서 **제외 태그 목록을 AI 가 정했다.** 계측으로 지표를 냈고,
2종은 넣고 1종은 보류했다. 그 판단 자체는 계측에 근거가 있지만 —
**사용자에게 선택지를 주지 않으면 [표시②] 관점에서 AI 의 판단이 사용자를 대신 결정한다.**

`PLAN_log_cpu_noise_filter` §10-3 에 남긴 판단 지점:

| 태그 | 계측 | 내가 한 판단 | 사용자라면 |
|---|---|---|---|
| `ActivityManager` | 잔여 40.4% · 94% 가 동일 줄 · **범인 앱 이름 포함** | 남겼다 | ? |
| `PermissionService` | 590줄 · 1종류 | 보류했다 (6.7% 뿐) | ? |
| `DeviceStorageMonitorService` | 332줄 · 2종류 | 보류했다 | ? |

**이 표를 없애야 한다** — 판단을 목록이 아니라 **선택지** 로 바꾸는 것이 목표.

## 1. 설계 제약 3가지

### ① 추가 adb 트래픽 0
기기가 이미 보내는 줄에서 계산한다. 새 adb 명령을 띄우지 않는다.
(별도 `logcat` 을 하나 더 띄우는 순간 **CPU 작업의 이득이 반납된다** — 같은 비용을 두 번 낸다)

### ② 부트스트랩 문제 — "시끄러운 걸 보려면 봐야 하고, 본 순간 더 이상 안 온다"
현재 구조는 `<tag>:S` 로 **기기에서** 거르므로, 제외한 태그의 줄은 **더 이상 도착하지 않는다.**
→ **무엇을 숨겼는지, 얼마나 숨겼는지가 개방 이후 사라진다.** 사용자가 되돌리려면 추측해야 한다.

**해결 — 제외된 태그의 집계는 얼어붙는다(freeze).**
- 집계표는 태그별로 `{건수, 서로 다른 메시지 표본, 제외됨 여부}` 를 갖고 있다
- 제외하면 **마지막 집계값을 유지**하고 상태만 `제외됨` 으로 바꾼다
- 사용자는 "내가 뭘 숨겼고 얼마나였는지" 를 **끝까지 본다** → 되돌리기가 정보가 된다
- 재포함하면 집계가 **다시 살아난다**(집계는 이어 붙는다 — 창을 닫을 때까지)

### ③ 집계는 세션 스코프, 선택만 영속
- **저장하는 것**: 사용자가 고른 태그 목록 (`relay.logs.excludedTags`)
- **저장하지 않는 것**: 집계값
  - 이유: 집계 영속화는 스키마·마이그레이션·손상 복구를 **먼저 얹어야 한다**
    (R6 에서 저장 실패 무음으로 큰 수를 냄). 이 기능의 가치는 "지금 본 것" 을 고르는 것이지
    "지난 일주일 통계" 가 아니다
  - 대신 배지에 **"창을 연 뒤 기준"** 을 명시한다 — [표시②]
- 집계 총량 상한 **200,000줄** — 초과하면 "집계 한도 도달" 을 정직하게 표시하고 멈춘다
  (제외를 꺼 둔 상태 2.2만 줄/초 환경에서 줄마다 파싱을 더 얹는 것을 막는다)

## 2. 마이그레이션 — bool → 배열

종전 저장 키 `relay.logs.excludeNoisyTags`(Bool) 를 배열 키로 옮긴다.

| 기존 상태 | 초기값 |
|---|---|
| 배열 키 없음 + bool 이 `false` (사용자가 껐음) | `[]` (의사를 존중) |
| 배열 키 없음 + 그 외 | 기본 시드 3종 |

`UserDefaults.object(forKey:) == nil` 로 "저장 전" 과 "빈 배열" 을 구분한다
(`bool(forKey:)` 는 저장 전 값이 false 가 되어 기본값이 깨진다 — `WifiAdbLogic.autoModeKey` 와 같은 함정)

## 4. 순수 로직 (테스트 가능한 형태로 떼어 낸다)

### `LogcatLine.parse(_:) → LogcatLine?`
`-v time` 형식: `09-28 02:03:02.326 W/dumpsys( 25283): Thread Pool …`
→ `레벨` / `태그` / `pid` / `메시지`. 파싱 실패는 `nil` (**조용히 넘기지 않고** 실패도 세지 않는다).
구획선(`--------- beginning of main`)은 태그가 없으므로 자연히 제외된다.

### `LogcatTagStats`
- `record(_ line: LogcatLine)` — 태그별 건수 +1, 메시지 표본 상한 5개
- `snapshot(maxTags:)` — 건수 내림차순 상위 N. `messages` 가 5에 닿으면 **"5종 이상"** 으로 표시
- `setExcluded(_:)` — 제외된 태그의 집계는 **값을 유지한 채 상태만 바꾼다**
- `totalRecorded` 상한 — `capped: Bool` 로 노출

## 5. UI

푸터의 `기기에서 N개 태그 제외` 배지를 **버튼**으로 바꾼다 → popover(`arrowEdge: .bottom`,
`FloatingGraphView` 의 불투명도 popover 와 같은 문법):

- 헤더: "태그별 반복 상위" + **"창을 연 뒤 기준"** 명시
- 목록(상위 8): 태그명 · 건수 · `N종 메시지` / 체크박스(제외 여부)
- 제외된 태그는 **"제외됨 · 마지막 N건"** 으로 표시하고 **회색** — 되돌리기가 가능해야 한다
- 하단: `기본값 복원` (시드 3종) · 집계 0이면 **"아직 데이터 없음"** (0건이라고 하지 않는다 — 표시②)
- 다크 고정 (로그 창 규칙 그대로)

## 6. 하지 않는 것

- **자동 감지** — 반복도가 높으면 AI 가 알아서 숨긴다. [표시②] 위반이며, 선택지 UI 가 먼저다
- **일주일 누적 집계** — 필요한 게 아니라 **부담**이다. v1 은 "지금 본 것" 이다
- **앱(package) 단위 필터** — 태그 ≠ 앱. 같은 태그를 여러 앱이 쓴다
- **`ActivityManager` 자동 포함** — 이건 사람이 판단할 몫이다

## 8. 구현 결과 — 계획이 틀린 곳 두 군데

### 8-1. AX 계층이 비어 있었다 — 클릭 자동화가 불가능했다
`System Events` 의 `entire contents of window` 가 **0개**. SwiftUI 내용이 보조기술에 노출되지 않는다.
→ 팝오버 **클릭 자체를 자동 검증할 수 없다.** 육안 대기 항목이 된다.
대신 **"저장 배열 → adb 자식 인자"** 경로를 끝까지 실측했다(3종/4종/빈 배열 3가지).

부수로 확인된 사실: 이 앱의 로그 창은 **VoiceOver 로도 내용을 읽을 수 없을 가능성이 있다.**
배지 버튼에는 `.accessibilityLabel` 을 붙였지만, 창 전체의 노출은 별도 과목이다.

### 8-2. 계측이 아니라 **크래시 리포트**가 한계를 알려줬다
`EXC_BREAKPOINT` / `SIGTRAP` — `LineParser.parse` 의 `index(after:)` 오버런.
```
RelayConsole-2026-09-28-024513.ips
  frames: _StringGuts.validateCharacterIndex ← String.index(after:)
          ← LogcatFilter.LineParser.parse ← LogcatStreamer.append
```
- **단위 테스트는 이 결함을 통과시켰다** — 내가 만든 *정상 형식* 만 넣었기 때문이다
- 위험 지점은 두 곳이었다: 빈 메시지(`)` 가 마지막 글자) · `/` 로 시작하는 줄(`index(before:)`)
- 로그 줄은 **기기에서 오는 데이터**다. 내 문법이 맞다는 보장은 없다
